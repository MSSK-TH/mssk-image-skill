v1.6.1 聊天新增 GPT-6.2、参考图路由收口与故障后路边界（2026-11-24）
------------------------------
  · 聊天模式（`chat`）新增实测校验的 **GPT-6.2** 家族（排在最前）：
      - 思考档 `gpt-6-2-thinking`（`standard` / `extended`）、即时档 `gpt-6-2-instant`（`none`）；
      - 小数点误写 `gpt-6.2-thinking` / `gpt-6.2-instant` 在 CLI 提前告警、服务端自动归一防 422。
  · 彻底修复参考图生图因画幅不同被误切去 `reference`（`/v1/responses`）的严重路由 bug：
      - `SKILL.md` 移除了 `reference` 主路由并写死硬规则：**任何带参考图的生图/改图，无论目标画幅（3:4、16:9、9:16 等）是否与原图一致，一律走网页管线 `edit --image`**；
      - 内联比例表补齐 `3:4` (`1086x1448`) 与 `2:3` (`1024x1536`)，减少翻阅 `references/cli.md`；
      - `image_gen.py` `_edit()` 在 `openai-multipart` 中同步透传显式 `size` / `quality`（配合 DMIT `server.mjs` `/v1/images/edits` 的 `foldParams`，`--size auto` 时仍 100% 原样直发）。
  · 明确并锁死「原生仅作网页管线故障后路」边界（CLI 文档 + DMIT `server.mjs` 双端一致）：
      - 网页管线遇到内容安全/政策拒绝（`e.refusal`）时直接原样返回，**严禁重开新对话重试或降级切去原生**；
      - 仅当网页管线本身不可用（连接故障/超时/Cookie 失效/403 不可用）或用户明确点名时才走 `codex-gpt-image-2`。
  · 配合 DMIT `webpipe.mjs` 对照 2026-11-24 浏览器抓包完成官方参考图请求体校准（`sediment://`、`attachments[].mime_type` + `source:'local'`、`/files` 与 `/prepare` 预热字段对齐）。
  · 自检 77 项 → **78 项**。

v1.6.0 网页直通极速模式与同对话改图对齐（2026-11-24）
------------------------------
  · 明确双管线职责边界（网页直通 vs 原生结构化）：
      - 网页管线（`gpt-image-2`，默认）定位于纯直通发射器：CLI 默认 `--no-augment`，原样直发用户提示词（不再包 `Primary request:` / 14 行模板），把理解与优化留给远端 ChatGPT 网页大脑；
      - 原生管线（`codex-gpt-image-2`）保持自动 `--augment` 提示词结构化，互不干扰。
  · `SKILL.md` 精简为高密度执行手册（~105 行），彻底砍掉 Codex 端多轮空转：
      - 内联 `chat` / `work` 完整模型与档位速查表（禁止生图前调 `tiers`、禁止无故 `--dry-run`、禁止默认 `view_image`）；
      - 合并提示词写入与启动为单条命令（短提示词直接 `--prompt`，多行用同命令 PowerShell here-string）；
      - 拉高 `yield_time_ms: 120000` 减少中途轮询；
      - `image_gen.py` 写盘后直接输出 `Wrote <绝对路径> (<宽>x<高>, <大小>KB)`，彻底免去出图后再起 shell 核验文件尺寸；
      - `bin/run.ps1` 仅在需要 Pillow 的参数时才探测 `import PIL`，省掉冷启动开销。
  · 对齐网页端会话续接与改图体验（配合 DMIT `server.mjs` 修复）：
      - `edit` 默认改为优先走 `openai-multipart`（与 `image-web` 100% 同协议，直接透传 `web_conv_key / web_mode / web_model / web_effort / background` 且省去 33% base64 编码；遇不支持 multipart 的中转再延迟回退 `codex-json`）；
      - 同一 Codex 对话 = 同一网页对话：默认全程复用同一会话钥匙，不再擅自 `--new-conv`；
      - 修改当前对话刚生成的图（网页管线）直接走 `generate` 原地追问修改（不重传原图 `--image`）；仅附加外部/本地图或走无状态原生端点时走 `edit --image`。
  · 自检 72 项 → **77 项**。

v1.5.3 档位别名防呆与单选交互优化（2026-11-23）
------------------------------
  · 彻底封堵网页管线档位别名 422（与 DMIT 服务端 webpipe.mjs 双端对齐）：
      - `--effort high` 自动映射为 `extended`，`--effort medium` 自动映射为 `standard`（chat / work 通用，解决 Agent 把“高”传成 `high` 触发上游 422 Invalid conversation body）；
      - `work` 下 `minimal` / `low` 自动映射为 `min`；`chat` 思考模型下 `minimal` / `low` / `min` 自动映射为 `standard`；
      - `setup` 写入时同样自动归一化，杜绝把 `high`/`medium` 持久化进 `config.json`。
  · 优化选模型与选档位交互体验：
      - `SKILL.md` 明确要求**模型**与**档位**必须拆成**两道独立单选**（支持多题表单时拆两道独立单选题，纯文本时分两轮单选），禁止合在同一题里让用户回 `(1,2)` / `(1,3)` 坐标对；
      - `tiers --mode <chat|work>` 新增 `--models` 选项（与现有 `--efforts` 对称）。

v1.5.2 交互策略与错误细节优化（2026-11-23）
------------------------------
  · 新对话生图交互升级为「全局兜底 + 按对话生效（方案 A）」：
      - `setup` 新增 `--ask-policy confirm|remember`（默认 `confirm`），`setup --show [--json]` 暴露 `web_ask_policy` 字段；
      - `confirm`（默认）：每个新对话第 1 次网页生图仅问 1 句「沿用默认还是换一个」（若提示词里已指定模型/模式则跳过）；选「换」后走两步选择且**仅通过命令行参数作用于当前对话**（不覆盖全局 `config.json`，除非用户明确要求设为默认）；同一对话内后续不再复问；
      - `remember`：静默沿用全局默认并 1 行报备（适合零打断偏好）。
  · `relay_errors.py` 的 `humanize_moderation_text` 保留服务端附带的 `· 网页管线先降级：...` 线索，并修正类别正则分号边界。

v1.5.1 实测校准与诊断加固（2026-11-23）
------------------------------
  · 修复 chat 模式 GPT-5.6 Sol 的真实 slug：由错误的 `gpt-5.6-sol-thinking` 改为实测真值 `gpt-5-6-thinking`（即时档 `gpt-5-6-instant`，GPT-6 即时档 `gpt-6-instant`），消除 prepare 阶段 `conduit_token` 失败降级。
  · 修复 work 模式档位全面错位与 422 报错：
      - `EFFORT_ORDER` 补入上游真实轻度值 `"min"`；
      - `WEB_WORK_TIERS` 对齐上游真实 5 档：`轻度(min) / 中(standard) / 高(extended) / 极高(xhigh) / 最高(max)`；
      - `work` 模式下历史写法 `--effort minimal` 自动映射为 `min` 并给明确告警，消除 `422 Invalid conversation body`；
      - 传旧错误 slug（`gpt-5.6-sol-thinking`）、`-instant` 搭思考档或跨模式混用 `-wm` 时提前给出告警。
  · 细化网页管线降级/失败诊断：
      - `relay_errors.py` 新增 `webpipe_invalid_request`（`conduit_token` / `422 Invalid conversation body`，不重试）与 `webpipe_blocked`（`webpipe 403` / Cloudflare / Sentinel，不重试）；
      - `_report_pipeline` 降级警告附带诊断建议，`_report_record` 补齐独立 `"degraded_reason"` 字段；
      - `_resolve_timeouts` 按显式 `--timeout` 缩放 `slow_after`（`min(base_slow, max(20, timeout*0.6))`），避免重任务短超时下 `[slow]` 永不触发。
  · `WEB_WORK_MODELS` 按上游版本选择器新到旧排序（6.2 Astra → 5.6 Luna，共 10 个已核验 `-wm` 模型），同步更新 SKILL.md / cli.md / relay-api.md / selfcheck.py。
